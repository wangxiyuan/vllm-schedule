vLLM Scheduler · 调度过程可视化

驱动真实 vLLM Scheduler / AsyncScheduler（无需 GPU）· 逐步动画演示调度决策、CPU 对象与 GPU 张量变化、KV 缓存生命周期

怎么读这个教程： 顶部选场景 → 中间的「本步发生了什么」逐帧讲解 → 下面的 CPU 侧（调度器 Python 对象）与 GPU 侧（模拟张量）面板展示对应状态。 被高亮/闪烁的元素就是本步发生的变化——先看讲解，再看高亮，最后看全貌。

每一帧 = 调度器的一次 schedule()（产生调度决策）和随后的 update_from_output()（应用模型输出）。帧反映「调度后、更新前」的瞬间。

时间线圆点的颜色表示该步事件：蓝=prefill 调度、 紫=投机 draft、红=抢占、 灰=完成、绿=全部完成。 一眼看到整个场景的「剧情走向」。

交互： 点请求卡片可高亮它的 KV 块与缓存格；点块池方块可跳到对应缓存块。 键盘 ←→ 上/下一步，空格 播放/暂停，Home/End 首/尾步。 链接带 #场景/步数，可分享或刷新后保持位置。 播放时勾选「跟随写入」，画面会自动跟着新写入的缓存块走； 勾选「固定视口」（默认）时，讲解与面板放进高度恒定的可视区，页面不随步进跳动， 内容在可视区内滚动——取消勾选则回到流式长页面。

CPU 侧调度器里的 Python 对象：每个 Request 的 进度（computed/total token）、状态、所在队列；KV 块池的占用。
GPU 侧模拟的张量（不真占显存）：BlockTable （每请求的 KV 块行）、slot_mapping（CPU 块 → GPU slot）、 InputBatch。
blockKV 缓存的最小分配单元，固定 block_size 个 token。 每个 block 有 block_size 个 slot，每个 slot 存一个 token 的 KV。 块池的第 0 块是 null block（哨兵占位块），不存 KV、不参与分配，真实块从 blk 1 编号开始。
prefill / decodeprefill 计算整个 prompt 的 KV；decode 每步只算 1 个新 输出 token 的 KV。chunked prefill 把长 prompt 拆多步。
num_computed_tokens该请求已算出 KV 的 token 数（进度条）。 prefix cache 命中时会从命中处直接跳进。
slot每个 token 在 KV cache 里的位置 = block_id × block_size + 块内偏移。 格子柜里放大弹出的格子 = 本步刚写入的新 token。
max_num_batched_tokens每步最多调度的 token 数； max_num_running_reqs 同时运行的请求数上限。
preemption（抢占）KV 池不足时，请求被驱逐回 waiting， 其 num_computed_tokens 清零，已分配 block 释放。
